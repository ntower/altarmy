# Optional addon integrations — WoW Forever compatibility audit

Tracks whether each addon AltArmy TBC optionally integrates with (see [FEATURES.md](FEATURES.md#optional-addon-integrations)) has a WoW Forever-compatible build, and whether its exposed API/SavedVariables shape has changed in a way that would break AltArmy's integration code.

This is a **static/source research** pass only (addon changelogs, `.toc` files, public repos) — no live-client verification via `/altarmy debug dump` or in-game testing. See [WOW_FOREVER_COMPATIBILITY_RESEARCH.md](WOW_FOREVER_COMPATIBILITY_RESEARCH.md) for AltArmy's own Forever compatibility work (which *does* have live beta access and findings) and [DEV_DUMPS.md](DEV_DUMPS.md) for the live-client debug-capture tool that a follow-up live-verification pass on these integrations should use. WoW Forever context: `AltArmy.DataStore.IsWowForever` (`AltArmy_TBC/Data/DataStore/DataStore.lua`).

All integrations listed here are already accessed defensively in AltArmy's own code (nil/existence-checked, feature hidden or degraded when the addon is absent) — see `docs/FEATURES.md` and the per-file references below. This audit is about whether the *other* addon still works on Forever, not about AltArmy's own defensiveness.

Checked 2026-10-20: the integration code is as listed (Auctionator's has grown, see the table), and the live-verification pass suggested above has not been done. The upstream statuses are as of 2026-09-22 and have not been re-checked since; Zygor's launch target is still ahead.

## Findings

### CraftLib (no longer used)

AltArmy dropped its optional CraftLib integration on 2026-10-02. CraftLib never shipped a Forever build, so recipe skill, difficulty and source data were missing there. AltArmy now ships its own recipe tables for both clients, generated from client data (see `AltArmy_TBC/Data/DESIGN.md`, "Recipe data").

### TacoTip

No Forever build exists as of this check. Canonical upstream is [anzz1/TacoTip](https://github.com/anzz1/TacoTip) (CurseForge: "TacoTip (GearScore & Talents & Item Level) [Classic/TBC/WOTLK]"). Latest release v0.5.1 (2026-08-23) predates the 2026-09-17 beta; `.toc` declares only `## Interface: 11304` plus Classic/BCC/Wrath min-interface tags, nothing for Forever. Two independent post-beta Forever addon-compatibility surveys (a realmlist.org "Forever Beta Addon Census" and an accountshark.net "Known Issues Week 1" guide) don't mention TacoTip at all — no evidence anyone has even attempted a port.

`TT_GS:GetItemScore(ItemLink)` still exists in current source with the same signature AltArmy relies on (`return GearScore, ItemLevel, Red, Green, Blue`). AltArmy's `type(_G.TT_GS) == "table"` check will simply never fire on Forever until an upstream port appears — no breaking change to react to, just an inactive integration.

### GearScoreTBCClassic

No Forever build exists as of this check. [CurseForge: GearScoreTBCClassic](https://www.curseforge.com/wow/addons/gearscoretbcclassic) (maintainer "yrodrigez", a community fork of the maintainer-inactive [gk646/GearScoreClassic](https://github.com/gk646/GearScoreClassic)) has no public source repo for this specific TBC fork — only changelogs are readable. Latest release predates the Forever beta (~Feb–Mar 2026); supported flavors remain Classic 1.15.8 / Classic TBC 2.5.1–2.5.6 only, no Forever tag. Same two post-beta addon surveys checked for TacoTip don't mention this addon either.

Whether `GearScoreCalc:OnPlayerEquipmentChanged()` / the `GEAR_SCORE_CACHE` global table shape have changed is genuinely **Unknown** — no source was browsable, only changelogs, which describe scoring-formula tweaks (item-level formula, gem/enchant bonuses, hunter weapon weighting fix) but nothing about restructuring the public object/table. Weak evidence against breakage, not confirmation. Re-check once a Forever-tagged release ships or source becomes browsable.

**Cross-cutting context (both TacoTip and GearScoreTBCClassic):** per Blizzard UI-team statements relayed in community porting threads, WoW Forever shares "the vast majority of APIs available in 12.1.5" (Midnight-era/Retail) rather than Classic's — Classic-era addons don't load unmodified and need active porting work by their authors, not just a `.toc` interface bump. Neither addon shows evidence of such an effort as of this check.

### Zygor Guides

Confirmed **planned, not yet shipped**. [Zygor's own blog post](https://zygorguides.com/blog/zygors-world-of-warcraft-forever-guides-launching-this-november/) commits to Forever guide support bundled into the existing Zygor Elite subscription, but explicitly targets game launch (**2026-11-04**), not the beta that opened 2026-09-17 — "there are no plans to have guides ready for the beta." No Forever-capable build exists to inspect as of this check (2026-09-22).

Zygor is closed-source/commercial (zygorguides.com); confirmed from AltArmy's own `ZygorIntegration.lua` source that the global it depends on is **`ZGV`** (not `ZygorGuidesViewer`), calling `zgv:GetGuideByTitle(title)`, `zgv:SetVisible(nil, true)`, `zgv.Tabs:LoadGuideToTab(title, 1)`, `zgv:SetGuide(title)`, and reading `zgv.DIR`. These match the long-standing Classic-era shape visible in older community-mirrored/decompiled copies of the addon, but there's no way to confirm from public sources whether Zygor's not-yet-released Forever build keeps this API unchanged — especially given the same retail/Midnight-API-surface risk noted above for TacoTip/GearScoreTBCClassic. Re-check around the 2026-11-04 launch date.

### RestedXP (RXPGuides)

Open-source (CC BY-NC-SA 4.0) on [GitHub](https://github.com/RestedXP/RXPGuides), and under active, same-week development of WoW Forever (interface `16001`) support as of this check: the main `RXPGuides.toc` already declares `## Interface: 11509, 50504, 120100, 120005, 120007, 16001`, and the Lua source has explicit runtime detection (`gameVersion >= 16000 and gameVersion < 20000` → `addon.game = "FOREVER"`, `maxLevel = 60`). Releases as recent as 2026-09-22 are actively converting guide content to a `#forever` tag (v4.11.8/4.11.9), and 2026-09-20/21 releases added Forever zone routing (Teldrassil, Darkshore, Coldridge Valley, Tirisfal).

The SavedVariables globals AltArmy TBC reads/writes are unchanged: `.toc` declares `## SavedVariables: RXPData, RXPDB, RXPSettings, RXPString` and `## SavedVariablesPerCharacter: RXPCData, RXPCTrackingData, RXPCComms, RXPCSettings` — an exact match to all four globals AltArmy touches (`RXPSettings`, `RXPCSettings`, `RXPData`, `RXPCTrackingData`). The addon is still registered under the name `RXPGuides`, so `LibStub("AceAddon-3.0"):GetAddon("RXPGuides")` remains the correct lookup. The quest-reward-recommendation flags AltArmy's conflict dialog manipulates (`enableQuestRewardAutomation`, `enableQuestChoiceRecommendation`, `enableQuestChoiceGoldRecommendation`, `enableQuestChoiceAutomation`) still exist by name in current source, though the exact profile-table structure wasn't diffed field-by-field.

**Caveat:** `RXPGuides_TBC.toc` (the TBC Classic-flavored build, `## Interface: 20506` only) has **not itself** been updated to interface `16001` as of this check — Forever compatibility so far applies to the base/vanilla RXPGuides line, not confirmed for a TBC+Forever combination specifically. This is source-inspection confidence, not live-client verification.

Sources: [RestedXP/RXPGuides](https://github.com/RestedXP/RXPGuides) (`.toc`/`.lua`/releases), [CurseForge listing](https://www.curseforge.com/wow/addons/restedxp-guide) (lists Forever as a supported flavor).

### Questie

**Abandoned (no Forever build yet).** Canonical upstream is [Questie/Questie](https://github.com/Questie/Questie) (BCC flavor: `Questie_TBC.toc`). A shallow clone of current `master` (checked 2026-09-22) shows five flavor `.toc` files (`Questie_Vanilla.toc` 11508/11509, `Questie_TBC.toc` 20506, `Questie_Wrath.toc` 38002, `Questie_Cata.toc` 40402, `Questie_Mists.toc` 50503/50504) — no `Questie_Forever.toc` and no `16001` interface anywhere in the repo, including in release-packaging scripts. Third-party coverage (wowforeverbuilds.com/addons/questie, wow4ever.quest/en/addons) corroborates: an *unofficial* community Forever port exists that draws known Classic quests on the map, but Forever's ~1000+ new quests aren't in its database yet, and "the official Questie isn't compatible yet." A related upstream repo, [Questie/QuestieDB](https://github.com/Questie/QuestieDB) (PR #26, issue #23), shows the Questie team is actively laying groundwork for a Forever data flavor (temporarily aliased to a "Camelot" TOC suffix Blizzard used internally, both using interface `16001`), but that work hadn't landed in the main `Questie/Questie` addon repo as of this check.

**API/SavedVariables surface: unchanged (No).** `Questie_TBC.toc` still declares `## SavedVariables: QuestieConfig, QuestieProfilerEnabled` and `## SavedVariablesPerCharacter: QuestieConfigCharacter`, matching what AltArmy reads. Grepping current source confirms `Questie.db.char.journey` (which is the runtime handle backing the saved `QuestieConfig.char[key].journey` table) still stores entries exactly matching AltArmy's expectations in `DataStoreLevelHistory.lua`: `Modules/Journey/QuestieJourney.lua` builds level-up entries as `{ Event = "Level", NewLevel = level, Timestamp = time() }` via `PlayerLevelUp`, and `Modules/Journey/tabs/MyJourney/MyJourneyTab.lua` / `Modules/Journey/QuestieJourneyShare.lua` both read/validate `entry.Event == "Level"` and `entry.NewLevel` the same way. No drift found; AltArmy's `ImportLevelHistoryFromQuestie` should keep working unchanged against current Questie — the risk is entirely that Questie itself doesn't run on Forever yet, not an API shape change.

Sources: [Questie/Questie](https://github.com/Questie/Questie) (`master`, `.toc` files, `Modules/Journey/*.lua`, checked via local clone 2026-09-22), [Questie/QuestieDB PR #26](https://github.com/Questie/QuestieDB/pull/26), [Questie/QuestieDB issue #23](https://github.com/Questie/QuestieDB/issues/23), [wowforeverbuilds.com/addons/questie](https://wowforeverbuilds.com/addons/questie), [wow4ever.quest/en/addons](https://wow4ever.quest/en/addons).

### NovaInstanceTracker

**Confirmed working.** No public source repo exists (closed-source, distributed only via [CurseForge](https://www.curseforge.com/wow/addons/nova-instance-tracker), Wago, and a stale WowInterface mirror) — the "NIT" author is Venomisto/Novaspark-Arugal. CurseForge's file list (checked 2026-09-22) shows the addon's supported-flavor badges as "Retail", "Forever", "MoP Classic", "Titan Reforged Classic", "Classic", with the latest file v2.28 uploaded 2026-09-18 (one day after the beta opened 2026-09-17) — strong, current evidence of an explicit Forever build, distinct from the abandoned WowInterface mirror (stuck at v1.29, 2022) that predates it. Only a GitHub *backport to 3.3.5a* by a third party (disruption01/NovaInstanceTracker_3.3.5a_backport) exists publicly; it has no bearing on the real (closed-source) Forever build.

**API/SavedVariables surface: Unknown.** Because the addon is closed-source and undocumented, there's no way to statically verify whether `NITdatabase.global`'s shape — specifically the `levelLog[level] = { timestamp, zoneName, subzoneName, gold, played, playedSource }` structure `DataStoreLevelHistory.lua`'s `BuildMilestoneFromNITLevel`/`ImportLevelHistoryFromNIT` expect — is unchanged in the Forever build. AltArmy's own read is already defensive (`DS._ResolveNITGlobal` nil-checks `NITdatabase.global`, and per-field nil-checks in `BuildMilestoneFromNITLevel`), so a shape change would silently import less data rather than error, but this needs live-client verification (a `/altarmy debug dump` of `NITdatabase.global` on a Forever client) to confirm one way or the other — flagging as a good candidate for the live-verification follow-up pass.

Sources: [CurseForge: nova-instance-tracker files](https://www.curseforge.com/wow/addons/nova-instance-tracker/files/all) and [addon page](https://www.curseforge.com/wow/addons/nova-instance-tracker) (checked 2026-09-22), [WowInterface listing](https://www.wowinterface.com/downloads/info25910-NovaInstanceTracker.html) (stale, v1.29/2022 — not evidence against Forever support, just not the current build).

### Auctionator

**Confirmed working.** Current maintainer is "plusmouse" per [CurseForge](https://www.curseforge.com/wow/addons/auctionator) (checked 2026-09-22); latest file is v339, uploaded 2026-09-21 (the day before this check), with supported-flavor badges including "Retail", "Forever", "MoP Classic", "Titan Reforged Classic", "Classic" — same-week Forever support, actively maintained (v338 shipped 2026-09-19, v339 2026-09-21). The project's GitHub org is [github.com/Auctionator](https://github.com/Auctionator), but the main `Auctionator/Auctionator` repo and its wiki (`/wiki/API-Documentation`) both now 404 — the source appears to have gone private/closed at some point; the org's remaining public repos are auxiliary (locale packs, `BCC-Auctionator` — explicitly marked "older version... use the newer 9.1.* Auctionator builds instead", `PreserveAuctionatorAHScan`, etc.), none of which is the live addon source. This matches Auctionator's known history of closing its primary repository.

**API/SavedVariables surface: No (best-effort — not source-verified).** Because the current source isn't publicly browsable, this couldn't be diffed directly against `Auctionator.API.v1.GetAuctionPriceByItemID`/`GetAuctionPriceByItemLink`. Circumstantial evidence is reassuring: AltArmy's own `NetWorth.lua` already calls both with the two-argument `(CALLER_ID, itemID)` / `(CALLER_ID, link)` signature, matching the documented-elsewhere public `API.v1` convention (addon name + lookup key) that other third-party addons (e.g. a "Guild Bank Ledger" price-source integration, a "skillup-forever" reagent-cost helper) are currently coded against in the same way, as of 2026. No deprecation notices, `API.v2` references, or breaking-change reports were found in web search. This is **not equivalent to a source read** — treat as reasonably confident but unverified; a live-client `/altarmy debug dump` checking `NW.IsAuctionatorAvailable()` / an actual `GetAuctionPriceByItemID` call on a Forever client would close the gap.

Sources: [CurseForge: auctionator](https://www.curseforge.com/wow/addons/auctionator) and [files list](https://www.curseforge.com/wow/addons/auctionator/files/all) (checked 2026-09-22), [github.com/Auctionator](https://github.com/Auctionator) org page and [orgs/Auctionator/repositories](https://github.com/orgs/Auctionator/repositories) (main repo/wiki now 404), third-party API consumers found via web search (RussellFeinstein/guild-bank-ledger issue #196, cjber/skillup-forever issue #1 / PR #3).
